Bundle View

The Composition page showed how $extract turns answers into a clinical document — but it left you writing your own renderComposition() function to display it. <tiro-bundle-view> does that rendering for you. Hand it the whole $extract response Bundle and it lays out the Composition as a readable document: section titles with their LOINC codes, the generated narrative, and any extracted Condition, Observation, Procedure or DiagnosticReport attached inline under the section that references them — each with a collapsible detail panel and a raw-JSON toggle.

Example 1 — Rendering an extracted Bundle

Here is a finished $extract response — a colorectal resection report — passed straight to the component. The Composition has three coded sections; each references a discrete resource that renders as an inline, collapsible card. Click a card to expand its details, or use the JSON toggles below the document to inspect the raw resources.

Example 2 — Straight from $extract

The real workflow: fill a form, send the answers to $extract, and pipe the response Bundle directly into the view. This is the same call as the Composition page — but instead of a hand-written renderer, one assignment (view.bundle = bundle) draws the document. Edit a field and re-submit to watch it regenerate. (This template extracts only a Composition, so there are no inline resource cards — the view renders whatever the Bundle contains.)

<script>
  async function submitNote() {
    const response = document.querySelector("#note-form").getResponse();

    // POST QuestionnaireResponse/$extract with a Composition template
    const bundle = await runExtract(response);

    // One line replaces the renderComposition() from the Composition page:
    document.querySelector("#note-view").bundle = bundle;
  }
</script>
How it works. The component finds the Composition in the Bundle and renders its section[] — title, the section's code (shown as a LOINC badge), and the generated text.div narrative. Every other resource is matched against the section.entry[].reference values (by ResourceType/id or bare id): a match renders as a collapsible card inline under that section, and anything left over trails the document. Supply the Bundle either as a JSON-stringified bundle attribute or, as shown here, as the .bundle property — set the property after the SDK script has loaded (the element must be upgraded first) and the view re-renders reactively whenever it changes.
