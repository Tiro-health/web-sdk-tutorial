Questionnaire Retrieval

Before a form can be rendered, the right Questionnaire has to be found and loaded from the SDC server. This page shows the two retrieval patterns the Tiro SDC server supports: resolving a canonical reference and searching by clinical context. Both are plain FHIR GET requests, so you can call them with fetch, curl, or any HTTP client.

SDC server: https://sdc.tiro.health/fhir/r5

Resolve a canonical reference

$resolve turns a canonical reference into the concrete Questionnaire resource — this is how the form-filler loads a questionnaire from its canonical URL. It implements the CRMI $resolve operation. The canonical parameter may be versioned (url|1.0.0) or versionless (url, which resolves to the latest active/retired version). A missing match returns a 404 OperationOutcome.

Try it
Resolve a canonical reference to fetch the full Questionnaire.
Request
# Resolve a versioned canonical reference
GET /fhir/r5/Questionnaire/$resolve?canonical=http://templates.tiro.health/templates/example|1.0.0
Accept: application/fhir+json

# Versionless — resolves to the latest active/retired version
GET /fhir/r5/Questionnaire/$resolve?canonical=http://templates.tiro.health/templates/example

# Not found -> 404 OperationOutcome

Search by clinical context

When you don't have an exact canonical reference up front, search for questionnaires by clinical context. The context search parameter filters by the specialty usage context (the useContext whose value is a specialty CodeableConcept). Pass a FHIR token system|code — for example a SNOMED CT specialty code. Repeat the parameter to OR several values. Add _summary=true to skip the heavy item payload, _elements=url,name,status to cherry-pick fields, or _summary=count to get just the total. The response is a searchset Bundle.

Try it
Run a search to list matching questionnaires (metadata only).
Request
# Search by specialty usage context
GET /fhir/r5/Questionnaire?context=http://snomed.info/sct|394821009
Accept: application/fhir+json

# Metadata only — omits the item[] payload
GET /fhir/r5/Questionnaire?context=...&_summary=true

# Cherry-pick fields
GET /fhir/r5/Questionnaire?context=...&_elements=url,name,status

# Just the total count
GET /fhir/r5/Questionnaire?context=...&_summary=count

# OR multiple specialties — repeat the param
GET /fhir/r5/Questionnaire?context=...|394821009&context=...|408443003
